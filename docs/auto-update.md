# Windows / Linux 被控端的自动更新

Mac 两端见 [spec.md](spec.md)「Mac 自动更新」。这里说 Windows 与 Linux 被控端（`galaxy-worker` 的 `upgrade` 模块）。

目标：更新全程零交互。用户在本机或远程控制时在被控机界面上点「立即更新」、主控端在设备详情里点「升级被控端」，或者到了定时自动更新的时间，被控服务自己下载、换掉旧的、装上新的、重新启动、以新版本连回服务器，界面也自己换成新版本；新版本起不来或连不上服务器就自动换回旧版本。没有任何按钮、UAC、密码框；远程连接会随服务重启断开，被控端自己回来，主控端重连即可。

## 1. 三个入口，同一条路

| 入口 | 时机 |
|---|---|
| 本机控制接口 `ApplyUpdate`（桌面端界面「立即更新」、命令行 `lemon-galaxy-worker update`） | 立即执行，不等远程会话结束 |
| 主控端「升级被控端」（`MgmtReq::ApplyUpdate`，要控制权限、不能是临时协助） | 先查有没有新版本、立即回复版本号，再在后台做（回复发出去后才退出） |
| 定时自动更新（服务模式，设置里「自动更新」默认开） | 服务启动 10 分钟后第一次查，之后每 6 小时；有人正在远程就先不重启，10 分钟后再看，最多推迟 24 小时，之后照样更新 |

命令行 `update` 在服务运行时经本机控制接口交给服务做；服务没在运行时只在本机换程序文件（没有服务管理器拉起，也就没有试运行与回滚）。只有服务模式（`LEMON_GALAXY_SUPERVISED=1`）才向主控端报 `remote_update` 能力。

主控端界面（Windows 主控端 `UI/Hosts/DeviceUpgrades.cs`、`HostsViews.cs`）：能被控的设备（被控端，或带本机被控的 Mac 客户端；不含本机，Windows 客户端的被控由同机的被控端服务作为单独设备出现）在 `DeviceInfo.update_version` 不为空时，设备列表与概览卡片上标「可升级」（正在升级时换成「升级中」）。设备详情（不用先连远程）在连接方式下面显示新版本与当前版本和「升级被控端」，设备离线时按钮不可用并提示要在线；点了直接调 `Client::upgrade_device`，不再确认。进度就地显示：正在升级到 x（下载新版本 → 替换并重启 → 以新版本上线三步，`on_started` / `on_offline` 推进）→ 已升级到 x（或失败原因与「重试」）；进行中按钮不可用，进度按设备记在主控端，离开详情再回来还在。结束后刷新设备列表；不在看这台设备的详情时另弹一条提示。

## 2. 换什么

- 装了桌面端：换整套。
  - Windows：`%ProgramFiles%\LemonGalaxy\Worker` 里有 `LemonGalaxyWorker.exe` 与 `lemon-galaxy-worker.exe`。下桌面端压缩包（组件 `worker-desktop`，平台 `windows` / `windows7` / `windowsxp`，与被控服务的平台名相同），解开后逐个文件换：界面、`.exe.config`、`Resources\`、被控服务（最后换）、许可证；新包里没有的旧文件不动。
  - Linux：deb / rpm 装的（以 root 运行、程序就是 `/usr/bin/lemon-galaxy-worker`、`dpkg-query` / `rpm -q` 查得到包）。下新的安装包（平台 `linux-deb` / `linux-rpm`），由包管理器装。
- 只装了 CLI（或服务器还没有桌面端的包）：只换核心程序（组件 `worker`，与以前一样）。
- 桌面端按「被控服务与界面里较旧的那个版本」问服务器：以前只换过核心、界面落后时，同版本的桌面端包也会装上把界面补齐。界面版本读不出来时按上次确认过的桌面端版本算，不会反复装。
- 服务器把发布里的桌面端包一起镜像（`galaxy_proto::update::classify_asset`）；还没升级的服务器没有 `worker-desktop`，被控端退回只换核心程序，界面下次再换，不报错。

## 3. 步骤

1. 检查：发布签名、文件在签名清单里（galaxy-client）；记在坏版本名单里的版本跳过。
2. 下载到数据目录 `update/staging`，核对 SHA-256。检查后服务器换了版本时按文件的 SHA-256 认出实际下到的是哪个版本。
3. 试跑新程序的 `version`（Windows 桌面端解开压缩包后试跑里面的被控服务，Linux 安装包用 `dpkg-deb -x` / `rpm2cpio` 解出来试跑）：缺系统函数、架构不对、文件坏了、报的版本不对就不装，旧版本照常运行。
4. 备份要换掉的文件到 `update/backup`；把当前（旧）程序复制成更新守护进程 `update/guard/<时间>/lemon-galaxy-worker[.exe]`；写 `update/state.json`（试运行、截止时间默认 10 分钟）。
5. 启动更新守护进程（`__lg-update-guard`），等到它的第一次心跳才动文件，起不来就不换：
   - Linux：`systemd-run` 放进单独的单元 `lemon-galaxy-worker-update-<时间>`（不是 root 时 `--user`），被控服务重启、包脚本重启服务都不会连带结束它；没有 systemd 时作为独立进程组的子进程（服务单元是 `KillMode=process`）。
   - Windows：不挂控制台、新进程组的子进程（服务进程退出不影响它）。
6. 换文件：先把新内容放到目标旁边再改名换上；Windows 上运行中的程序（被控服务、界面、会话代理）不能覆盖但能改名，把旧的挪成 `*.old.exe` / `*.old-N.exe`，确认后删。
7. 重启：被控服务以退出码 75 退出。Windows 服务管理器把「没报告已停止就退出」当作意外退出，按恢复操作 3 秒 / 10 秒 / 30 秒后重启（之后每次 30 秒，XP 起都支持；服务每次启动时会再核对一遍恢复操作）；systemd `Restart=always`。Linux 安装包不退出：守护进程调 `dpkg -i` / `rpm -U`（dpkg 锁被占时等一会再试，最多 6 次），包的 postinst 重启服务；包装好 45 秒新版本还没启动就由守护进程重启一次。
8. 新版本启动最早的时候（`run` / `service` 命令解析完参数、还没联网）把启动次数加一；守护进程不在（比如中途重启了电脑）就按记下的旧程序再拉起来。程序被手动换成了既不是旧版本也不是新版本时作废这次更新。
9. 确认：新版本连上服务器并稳定 60 秒后改成 `committed`，删备份与挪开的旧文件；Windows 桌面端还把「应用和功能」里的版本号改成新版本。离截止时间不到 10 秒就不确认，交给守护进程。

## 4. 回滚

守护进程（旧版本程序）每 2 秒看一次：

- 新版本启动超过 3 次还没确认（起来就崩，被服务管理器一次次拉起）；或
- 到了截止时间还没确认（起不来、一直连不上服务器、卡住）；

就停服务（Windows 30 秒停不下来就结束进程）、按备份换回所有文件（新版本新加的文件删掉）、把这个版本记进坏版本名单（`state.json` 的 `bad`，最多 20 个）、清掉 systemd 的失败计数后启动服务。坏版本不再自动安装，「立即更新」也不装（显示已是最新）；有更新的版本时照常装。包没装上（dpkg / rpm 失败）同样换回文件，但不算坏版本。日志：守护进程写数据目录 `logs/update.log`，装包输出在 `update/install.log`，服务自己的日志照旧。

`state.json` 的读改写拿 `update/state.lock`（独占新建，30 秒前的锁作废）；确认与回滚都先在锁里改阶段，谁先改到谁做，另一方不再动手。

Linux 安装包换回的是 `/usr/bin` 下的两个程序，包管理器里记的仍是新版本号；之后有更新的版本时照常用包管理器装。

## 5. 界面自己换成新版本

- Windows WPF 版、老系统原生版：装在 Program Files 的那份每 10 秒看一次安装位置上界面程序的文件版本，连着两次与自己不同就以同样的方式打开新版本接替自己（`--replace`，窗口没开时加 `--background`：只放托盘、不看「登录后在托盘显示」），旧进程收到退出信号后退出；单实例按安装位置算，挪开的旧程序与新程序算同一个。新版本一分钟内没接替就接着看着。
- Linux GTK 版：每 10 秒看 `/proc/self/exe` 是否已被换掉（包管理器写新文件再改名），连着两次看到、新程序 `--version` 能正常退出，就把打开的文件都设成 exec 时关闭，原地 exec 成新程序（进程号不变，登录自启动的单元不受影响），窗口没开时加 `--tray`；新进程带 `--restarted`，会话总线上的名字还没释放时多等一会再注册。
- 不弹任何提示。服务换回旧版本时，界面同样会换回来。第一次从没有这个功能的旧版本升级时，旧界面不会自己重启，下次登录时换成新版本。

## 6. 测试

- 单元测试：发布文件分类（galaxy-proto）、桌面端按哪个版本问、换文件与挪开运行中的程序、压缩包解开（反斜杠、目录穿越、损坏）、进度记录与锁、确认、回滚（换回文件、删新加的文件、记坏版本、停 / 启服务）、守护进程的两种回滚条件、启动记账、不开服务时只换文件（galaxy-worker）；界面重启参数（Linux 界面）。
- 端到端：`scripts/e2e-update.sh`（CI 的 Linux 与 Windows x64 任务）把测试构建的被控端装成 systemd / Windows 服务，经本机控制接口「立即更新」：好版本换上、自己重启、连回服务器、确认、主控端连得上（Windows 还核对桌面端的界面、资源、许可证都换了）；文件坏了的版本试跑就被拒；起来就崩的版本被换回并记成坏版本、之后不再装；Linux 再测一直连不上服务器的版本到期换回。`--deb` 在「Linux 被控端界面与安装包」任务里装旧版本的 .deb，经自动更新换成新版本的 .deb（守护进程调 dpkg、包脚本重启服务、开机自启保留）。开发机上没有 systemd / 管理员权限时用 shell 循环代替服务管理器。
- 「可信的新版本」：正式发布私钥只在发布任务里。测试构建打开 `galaxy-proto` 的 `test-release-key` 特性，`RELEASE_SIGN_PUBKEY` 换成测试密钥（私钥种子公开写在测试脚本里），只认测试密钥、不认正式密钥；特性默认关，发布构建从不打开，发布任务还会核对发布的程序里没有测试公钥。测试构建的版本编成 `9.8.7.6000`，脚本把程序里的版本串原样改成 `9.8.7.6001` 等做出新版本；坏版本用测试构建里才生效的故障标记（起来就崩 / 不连服务器），正式构建不看它。
- 还没在真机上验证：XP / Vista / 7 上的服务恢复操作与改名替换、界面接替；rpm 系统上的装包；Linux 界面原地 exec。
