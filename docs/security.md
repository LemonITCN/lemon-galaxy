# 安全设计

## 1. 威胁模型与目标

需要防住的对象：

1. 网络上的窃听与中间人（公共 Wi-Fi、运营商、局域网里的其他设备）。
2. **服务器被攻破**（VPS 被黑、数据库被拖、管理员账号被盗、服务器程序被替换）。
3. 账号密码泄露或被暴力破解。
4. 主控设备（电脑 / 手机）丢失。
5. 恶意或被诱导的大模型（提示注入、乱执行危险命令）。
6. 协议解析漏洞（远程代码执行）。
7. 供应链（依赖、构建流程、更新包被篡改）。

核心目标：

- **服务器被完全攻破，攻击者也控制不了任何一台被控设备，也读不到任何会话内容、主机密码和私钥。**
- 被控端的机主对本机始终有最终决定权，任何远端（包括服务器和主控端）都改不了被控端本地的安全设置。

## 2. 密钥体系

| 密钥 | 类型 | 生成位置 | 保存位置 | 用途 |
|---|---|---|---|---|
| 服务器 TLS 密钥 | ECDSA P-256 | 服务器首次启动 | 服务器数据目录 | 客户端 ↔ 服务器 TLS；客户端固定指纹 |
| 服务器签名密钥 | Ed25519 | 服务器首次启动 | 服务器数据目录 | 签发「连接票据」，让被控端确认这次连接经过了服务器授权 |
| 服务器主密钥 | 32 字节 | 服务器首次启动 | 服务器数据目录（与数据库分开的文件，权限 0600） | 加密数据库里的大模型 API Key、TOTP 密钥 |
| 账号签名密钥 | Ed25519 | 用户第一次登录的客户端 | 服务器上只存「被密码派生密钥加密后的密文」 | 给设备签发证书、签吊销列表 |
| 账号加密库密钥 | 32 字节对称 | 同上 | 同上 | 加密 vault（文件夹、别名、SSH/RDP 主机、密码、私钥、片段） |
| 设备身份密钥 | Ed25519 | 每台设备安装时 | 设备本地安全存储（Keychain / Android Keystore 包裹 / DPAPI / Linux 0600 文件） | 设备身份、端到端握手签名 |

账号签名密钥和加密库密钥合称「账号机密」，打包后用 XChaCha20-Poly1305 加密：

```
kek = HKDF-SHA256(ikm = OPAQUE export_key, salt = account_id, info = "lemon-galaxy/account-kek/v1")
wrapped = XChaCha20Poly1305(kek, nonce, plaintext = 账号机密, aad = "lemon-galaxy/account-secrets/v1" || account_id || epoch)
```

服务器只存 `wrapped`。只有知道账号密码的客户端，在本地跑完 OPAQUE 拿到 `export_key` 才能解开。

## 3. 账号登录：OPAQUE

- 使用 OPAQUE（RFC 9807，`opaque-ke`，套件 Ristretto255 + Argon2id）。服务器只保存 OPAQUE 注册记录，**从头到尾见不到密码**；数据库被盗也无法离线撞库（需要服务器私钥参与才能验证猜测）。
- 管理员创建用户时设初始密码：服务器在内存里用这个初始密码代替客户端完成一次 OPAQUE 注册，随即丢弃密码，并标记「必须改密码」。
  用户第一次在客户端登录后，客户端强制改密码（重新注册 OPAQUE），并生成账号机密、上传 `wrapped` 与账号公钥。此后服务器和管理员都不再知道密码。
- 用户自己改密码：客户端用旧机密重新包裹上传，账号密钥不变，各设备无感。
- 管理员重置密码（用户忘记密码）：服务器丢弃 `wrapped`，账号 `epoch` 加一。旧 epoch 签的设备证书全部失效，该账号需要在各台设备上重新登录一次。这是「服务器拿不到账号密钥」的必然代价，用户已确认接受。
- 两步验证：TOTP。普通用户可自行开启，管理员可对用户强制开启；管理员自己强制开启。
- 防暴力破解：按账号和来源 IP 计数，连续失败达到阈值（默认 5 次）锁定（默认 15 分钟），全部记入审计日志。
- 会话令牌：256 位随机数，服务器只存哈希，绑定设备 ID；建立 WebSocket 时还要用设备身份密钥签服务器下发的随机挑战，令牌被偷也无法在别的设备上用。管理员可一键注销某用户的全部会话。

## 4. 设备证书

设备登录账号后，用账号签名密钥给自己的设备公钥签一张证书：

```
DeviceCert {
  v: 1,
  account_id: u64,          服务器上的用户 ID
  account_epoch: u32,
  device_id: [u8; 16],
  device_pubkey: [u8; 32],  Ed25519
  kind: Control | Worker | Mobile,
  issued_at: i64,           Unix 秒
}
signature = Ed25519(account_sign_key, "lemon-galaxy/device-cert/v1" || postcard(DeviceCert))
```

- **control / mobile**（主控设备）在本地安全存储里保留账号机密（用设备密钥包裹），用于访问 vault、签吊销列表。主控设备丢失时，用户在其他设备或管理员在后台吊销它。
- **worker**（被控设备）签完自己的证书后**立即丢弃账号私钥和 vault 密钥**，只留账号公钥和自己的证书。被控设备被攻破，攻击者也拿不到 vault，也签发不出主控证书。
- 吊销：
  - 服务器侧吊销（管理员或用户操作）立即生效：服务器拒绝为被吊销设备转发信令、签发票据。
  - 账号吊销列表由账号签名密钥签名，经服务器分发，被控端缓存。服务器不可达（离线局域网模式）时，以被控端最后一次同步的吊销列表为准。

## 5. 端到端会话认证

两端之间是 QUIC（TLS 1.3）。每台设备用自己的设备身份密钥生成自签 TLS 证书，TLS 层只负责加密；身份认证在 TLS 之上做，并且绑定到这条 TLS 连接：

1. QUIC 握手完成后，双方从 TLS 导出 32 字节 `exporter = TLS-Exporter("lemon-galaxy/session/v1", 32)`。
2. 双方在控制流上互发 `Hello`：
   - 自己的设备证书（账号签名）；
   - `sig = Ed25519(device_key, "lemon-galaxy/session-auth/v1" || exporter || role)`；
   - 主控端附带服务器签发的连接票据（离线局域网模式没有）。
3. 校验：
   - 证书由对方声称的账号公钥签名，epoch 与本地记录一致，不在吊销列表里；
   - 证书里的设备公钥 == 对方 TLS 证书公钥，且 `sig` 有效（证明对方持有设备私钥、且就在这条 TLS 连接的另一头，中间人无法转接）；
   - 被控端：证书所属账号必须是本机已登录的账号之一；本机与服务器在线时必须带有有效票据（票据由服务器签名，含双方设备 ID、账号、过期时间、连接 ID）；服务器不可达时允许无票据（局域网离线模式）。
4. 任何一项不通过立即断开，并记入被控端本地日志。

服务器在这个过程里只能：拒绝牵线、拒绝中转。它没有账号签名密钥，**伪造不出被控端会接受的主控设备**；中转的只是 QUIC 密文。

### 5.1 临时协助

被控端未登录任何账号时，用设备身份密钥匿名连接服务器，服务器分配 9 位设备码；被控端本地生成验证码（8–16 位，可自动刷新或自定义），只显示在被控端屏幕上。

- 主控端必须是本服务器的登录用户（服务器据此记录是谁发起的）。
- QUIC 建立后，双方用 SPAKE2（口令 = 验证码，身份 = 双方设备 ID，附加数据 = exporter）完成口令认证。服务器不知道验证码，无法冒充任何一方；猜错立即断开，连续猜错锁定设备码。
- 认证通过后，被控端弹窗「某某（用户名）请求控制本机」，本人点允许才开始；协助期间被控端本地设置锁定，不允许远端修改验证码和验证方式。

## 6. 被控端本地安全

- 每个登录的账号单独设权限：查看画面、控制键鼠、文件、终端、剪贴板、声音、AI 上限（禁止 / 只读 / 每步确认 / 危险操作确认 / 完全信任）。这些设置**只在被控端本机修改**（Linux 用命令行，其余用本机界面），远端改不了。
- 终端 / 文件 / 命令执行以「该账号对应的系统用户」身份运行（被控端登录账号时指定；Linux 默认是执行登录命令的用户，选 root 要明确确认）。root / SYSTEM 服务本身只负责网络与认证，具体操作在以目标用户身份运行的子进程里做，权限由操作系统强制。
- 被控时显示提示（谁在控制、AI 是否在操作），提供一键断开、一键禁止远程。
- 本地记录每次连接、每个文件操作、每条命令（AI 发起的单独标记）。
- 可选：远程结束后自动锁屏。

## 7. 服务器安全

- 全部 Rust 编写，无 `unsafe` 业务代码。
- TLS 1.3（rustls）。客户端填写的服务器地址形如 `galaxy.example.com:7443#sha256-<指纹>`，后台「服务器信息」页直接给出这串，复制即可；客户端固定该指纹。也支持配置正规 CA 证书。
- Web 后台：HttpOnly + Secure + SameSite=Strict Cookie；所有写操作要求 CSRF 令牌；严格 CSP；登录限速；管理员强制两步验证；可配置只允许指定 IP 段访问后台。
- 数据库里的 API Key、TOTP 密钥用服务器主密钥加密；数据库文件与密钥文件权限 0600。
- systemd 单元带沙箱选项（`NoNewPrivileges`、`ProtectSystem=strict` 等），以专用非 root 用户运行。
- 中转：只转发已由信令授权的连接对之间的数据；按连接和总量限速；防止被当成开放代理。
- 审计日志：登录、改密码、设备登录与吊销、连接建立、后台所有管理操作；默认保留 180 天。

## 8. 工程安全

- 协议解析：所有帧有长度上限；反序列化失败即断开；对解析入口做模糊测试（cargo-fuzz）。
- 依赖：`cargo-deny` / `cargo-audit` 进 CI；锁定版本。
- Actions：第三方 Action 固定到提交哈希；默认只读权限；签名密钥只放在发布环境的 Secrets。
- 发布：每个发布文件附 SHA-256，并用 LemonGalaxy 发布签名密钥（Ed25519）签名；客户端内置公钥，自动更新必须验签通过才安装。
