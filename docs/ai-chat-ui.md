# AI 聊天界面（四端统一）

AI 页面是一个轻便的聊天窗口，像 ChatGPT / Codex / Claude Code 的对话界面：打开就能聊，需要时在消息里引用账号里的资源，
让模型边聊边查、必要时在设备上动手。不再有「先选模型、选目标、写任务、点开始」的表单。

Mac、Windows、安卓、iOS 交互一致；桌面端与手机端只在布局上不同（见第 6 节）。内核接口见 docs/ffi.md 第 2、6 节，行为见 docs/ai-agent.md。

## 1. 页面结构

- 左侧（手机端为对话列表页）：对话历史。顶部「新对话」按钮与搜索框；按「今天 / 昨天 / 最近 7 天 / 更早」分组；
  每行是标题（内核取首条消息前 40 字）与时间；右键（手机端长按）删除。正在进行任务的对话在行尾显示一个小的进行中标记。
- 右侧（手机端为对话页）：消息流 + 底部输入框。
- 新对话（还没有消息）：消息流位置居中显示一行问候「有什么可以帮你？」，输入框放在问候下方居中；发出第一条消息后输入框回到底部。
  不放示例问题、不放功能介绍。

## 2. 输入框

一个圆角容器，从上到下：

1. 引用标签行（有引用时才出现）：每个引用一个小标签（图标 + 名称 + 删除叉），可横向换行。
2. 多行文本框：桌面端 Enter 发送、Shift+Enter 换行；手机端回车换行、点发送按钮发送。最多长到约 8 行后内部滚动。
3. 底部工具条：
   - 左侧「+」按钮：菜单为 设备或主机 / 文件或文件夹 / 命令片段 / 端口映射 / 连接记录。
   - 模型选择：紧凑的文字按钮（当前模型名 + 下拉箭头），菜单按供应商分组，能看图的模型带「看图」小标记。
   - 权限档位：紧凑按钮（档位图标 + 名称），菜单四项：只读 / 每步确认 / 危险操作确认 / 完全信任；高于管理员上限的项置灰；
     选完全信任时让用户选时限（15 分钟 / 1 小时 / 本对话）。同一菜单底部一个勾选项「先出计划」。
   - 右侧发送按钮（圆形箭头）；任务进行中变成停止按钮（圆形方块），点了调用 `stop()`。
   - 文本与引用都为空时发送按钮置灰。

### 2.1 @ 引用

在文本框里输入 `@` 弹出候选（桌面端在光标附近浮出，手机端在输入框上方）：账号里的设备（不含本机与手机）与 SSH 主机，
按输入的文字过滤，显示平台图标、名称、在线状态。选中后删掉 `@` 及后面的过滤文字，加一个引用标签。Esc / 点空白处关闭。

### 2.2 「+」菜单

- 设备或主机：列表选择（同 @ 候选，可多选）。
- 文件或文件夹：先选设备或主机，再浏览目录（复用各端已有的文件浏览 / SFTP 列目录能力），可「选择这个文件」或「选择当前文件夹」。
  引用标签显示文件名，悬停 / 长按显示完整路径与所在设备。
- 命令片段、端口映射：从加密库条目里选（可多选）。
- 连接记录：直接加一个「最近连接记录」标签（不用选）。

引用转成 `ContextRef { kind, target_id, id, label }` 交给 `send_with_refs`：

| 引用 | kind | target_id | id |
|---|---|---|---|
| 设备 | Device | 空 | 设备 ID |
| SSH 主机 | SshHost | 空 | 加密库条目 ID |
| 文件 / 文件夹 | File / Folder | 设备 ID 或 SSH 主机条目 ID | 路径 |
| 命令片段 | Snippet | 空 | 条目 ID |
| 端口映射 | PortForward | 空 | 条目 ID |
| 连接记录 | Activity | 空 | 空 |

## 3. 发送与对话生命周期

- 新对话发第一条消息时才创建：`new_conversation(ConversationConfig { 当前模型, targets: [], 当前档位, plan_first, trust_minutes, title: nil })`，
  然后 `send_with_refs(text, refs)`。创建失败时消息留在输入框里，在输入框上方显示错误。
- 之后每条消息都用 `send_with_refs`。
- 中途换模型：`set_model(provider_id, model_id)`；中途换档位：`set_mode(mode, trust_minutes)`。
- 打开历史对话：`open_conversation(id, nil, listener)`，用 `messages()` 恢复消息流；输入框里的模型与档位取对话保存的配置。
- 默认值：档位默认「危险操作确认」（不超过管理员给的上限）；模型默认用本机记住的上次选择，没有或已不可用时取列表第一个。
  上次选的模型、档位、先出计划存在本机设置里。
- 手机端切到后台时照旧 `set_foreground(false)`。

## 4. 消息流

- 用户消息：靠右的气泡；引用标签显示在文字上方（来自 `AgentMessage::User.refs`）。
- 模型回复：不用气泡，占满宽度，按 Markdown 渲染（标题、列表、粗体、行内代码、代码块带语言名与复制按钮、表格、链接）。
  流式输出时逐字追加，末尾一个闪烁的光标。
- 思考过程（`Thinking`）：回复上方一行可折叠的「思考过程」，默认折叠，进行中时显示「正在思考」。
- 工具调用：一行紧凑的条目（工具图标 + 摘要 + 目标设备名 + 状态：进行中转圈 / 成功对勾 / 失败或被拒红色叉），点击展开：
  完整命令或参数、模型说明的理由、风险原因、输出（等宽字体，最多显示若干行可再展开）、截图缩略图（可点开看大图）。
  `use_target`（连接某设备）、账号查询（list_devices 等）也是这样一行。
- 需要确认（`ToolProposed.needs_approval`）：这一条展开成醒目的卡片：目标、完整命令 / 文件改动对比 / 点击位置、风险级别与原因、模型理由；
  按钮：允许一次、本对话内同类都允许、拒绝（可填理由）、修改后执行（只对命令）。`use_target` 的卡片只有「允许」和「拒绝」，文案「AI 想连接 某设备」。
- 提问（`AskUser`）：卡片列出选项按钮，另有文本框可自由回答。
- 要密码（`SecretRequested`）：卡片里一个安全输入框（不回显）与「发送」，内容走 `provide_secret`，不进入消息流。
- 错误（`Error`）：消息流里一行红色提示。
- 新消息到达时自动滚到底；用户往上翻看时不自动滚动，右下角出现「回到底部」按钮。

## 5. 不可用时的提示（不能让人发懵）

进入 AI 页面就调用 `ai_models()`，按结果显示，输入框在这些情况下不可用：

- 加载中：消息流位置一个小的加载指示。
- 加载失败：错误信息 + 「重试」按钮。
- 账号没开通 AI（`enabled == false`，或登录用户 `ai_enabled == false`）：
  居中一段说明「你的账号没有开通 AI 功能，请联系管理员开通。」
- 开通了 AI 但没有任何可用模型（`items` 为空）：
  居中一段说明「管理员还没有为你的账号开通任何模型。请联系管理员在管理后台的「用户」页为你开通模型。」+「重试」按钮。

## 6. 平台差异

- Mac / Windows：左右两栏（对话列表约 240 宽，可收起），消息流内容最大宽度约 760 居中。键盘：Enter 发送、Shift+Enter 换行、
  Esc 关闭弹出菜单、⌘/Ctrl+N 新对话。
- 安卓 / iOS：对话列表一页、对话一页（平板可两栏）；输入框随键盘上移；「+」菜单与选择器用底部弹层；@ 候选显示在输入框上方。
- 图标一律用矢量图标（各端已有的图标体系），不用 emoji；不堆说明小字，需要解释的放在 i 图标的气泡里。
